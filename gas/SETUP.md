# 導入手順（Google スプレッドシート版）

所要 20〜30分。プログラムの知識は不要です。

**対応バージョン：Code.gs（合言葉ログイン対応）／ index.html v4.2**

---

## この仕組みの概要

- 勤務表のデータは **Google スプレッドシート**に保存されます
- 職員は **部署ごとの合言葉**でログインします（Googleアカウント不要）
- 管理者は全部署、職員は自分の部署だけを扱えます

---

## 1. スプレッドシートを作る

クライアントの Google ドライブに新しいスプレッドシートを作成します。

- 名前の例：`勤務表データ`
- **共有ドライブに作成してください。** 個人のマイドライブに置くと、担当者の異動時にファイルが宙に浮きます
- **クライアント側のアカウントで作成してください。** 制作者個人のドライブに置くと、契約終了時にアクセスできなくなります
- 「新規 → Google スプレッドシート」で作ります。**Excel ファイルのアップロードでは動きません**

---

## 2. スクリプトを貼り付ける

1. スプレッドシートのメニュー → **拡張機能 → Apps Script**
2. 既定の `コード.gs` の中身をすべて消し、**`Code.gs` の内容を貼り付け** → 保存（⌘/Ctrl + S）
3. 左の「ファイル」の **＋ → HTML** をクリック
4. ファイル名を **`index`** にする（**`.html` は付けません**。自動で付きます）
5. 中身をすべて消し、**`index.html` の内容を貼り付け** → 保存

この状態になれば正しく貼れています。

```
ファイル
├ コード.gs
└ index.html
```

> ファイル名は必ず `index` にしてください。`Code.gs` から `index` を読み込んでいます。

---

## 3. 初期設定を実行する

1. 左の **コード.gs** をクリック（HTML を開いていると実行ボタンが出ません）
2. 上部の関数選択で **`setup`** を選ぶ
3. **▷ 実行** をクリック（「デバッグ」ではありません）
4. 初回は承認画面が出ます

```
権限を確認 → アカウントを選択
   ↓
「このアプリは Google で確認されていません」
   ↓
左下の「詳細」→「（プロジェクト名）に移動（安全ではないページ）」
   ↓
「許可」
```

**この警告は正常です。** 自作のスクリプトには必ず表示されます。

実行ログに「セットアップが完了しました」と出れば成功です。

スプレッドシートに以下のシートができます。

| シート | 内容 |
|---|---|
| 設定 | 管理者メール・部署・必要出勤人数 |
| 勤務予定 | 1行＝1人1日。人が読む用・分析用 |
| アクセスログ | ログインの記録 |
| 合言葉 | 管理者と部署ごとの合言葉（**非表示**） |
| _data | 保存の本体（**非表示**） |

---

## 4. 設定シートを編集する

| 項目 | 値の例 |
|---|---|
| 管理者メール | `shicho@example.jp, jimu@example.jp` |
| 部署 | `管理部, 事務, 診療アシスタント, 看護師, ドライバー, 戸塚院, 港南院` |
| 必要出勤人数 | `2` |

- **管理者メール**に登録した方は、Googleアカウントでログイン済みなら**合言葉なしで管理者として入れます**
- 師長が交代したら、ここを書き換えるだけです（プログラムの修正は不要）
- 部署を増減した場合は、後述の `resetPasscodes()` で合言葉を作り直してください

---

## 5. 合言葉を確認する

`合言葉` シートは非表示になっています。スプレッドシートのメニューから開きます。

```
表示 → 非表示のシート → 合言葉
```

| 対象 | 合言葉 | 更新日時 |
|---|---|---|
| 管理者 | k7m2xq4p | … |
| 看護師 | w3nf8t6r | … |

- **自由に書き換えられます。** 覚えやすい言葉に変更して構いません
- 紛らわしい文字（`l` `1` `O` `0`）を除いてあるので、口頭でも伝えられます
- 確認が終わったら、タブを右クリック → **シートを非表示** で戻してください

**すべて作り直したい場合**は、Apps Script で関数 `resetPasscodes` を実行します。

---

## 6. 公開する

1. エディタ右上の **デプロイ → 新しいデプロイ**
2. 歯車 → **ウェブアプリ** を選択
3. 設定
   - 説明：`v4.2`
   - **次のユーザーとして実行：自分**
   - **アクセスできるユーザー：全員**
4. **デプロイ** → 表示された **ウェブアプリの URL**（末尾が `/exec`）を控える

### 「全員」で問題ない理由

職員が Google アカウントを持っていないため、ログインなしで開ける必要があります。
**公開範囲を「全員」にしても、合言葉がなければ何も見えません。**
データの読み書きは、通信のたびにサーバー側で認証を確認しています。

### 実行アカウントに注意

**必ずクライアント側の担当者のアカウントでデプロイしてください。**
制作者のアカウントで公開すると、契約終了時にツールが停止します。

---

## 7. 動作を確認する

`/exec` の URL を開きます。

**管理者メールに登録済みのアカウントで開いた場合**

| 確認箇所 | 期待される表示 |
|---|---|
| ヘッダー左 | 管理者（メールアドレス） |
| 保存先 | ▦ 勤務表データ / Google スプレッドシート |
| 部署 | すべて選べる |
| 画面下部 | v4.2 |

**それ以外（シークレットウィンドウなど）**

紺色の背景にログイン画面が出ます。部署と合言葉を入力し、氏名を選ぶと勤務表が開きます。
職員は自分の部署のみで、部署の切り替えはできません。

**保存の確認**

氏名を1つ入力して、ヘッダーが「保存中…」→「保存しました HH:MM」と変われば成功です。
`_data` シートに行が増えているはずです。

---

## 更新のしかた

`index.html` や `Code.gs` を修正したら、

1. Apps Script の該当ファイルを差し替えて保存
2. **デプロイ → デプロイを管理 → 鉛筆マーク → バージョン「新バージョン」→ デプロイ**

**URL は変わりません。** 「新バージョン」を選ばないと反映されないので注意してください。

---

## 仕様と制限

| 項目 | 内容 |
|---|---|
| ログイン | 部署ごとの合言葉。管理者は専用の合言葉または管理者メール |
| 有効時間 | 6時間。切れたら再ログイン |
| 失敗制限 | 5回間違えると10分ロック |
| 保存 | 変更の 1.5 秒後に自動。同時保存は待ち合わせます |
| 保存単位 | 年月 × 部署 |
| 1件あたり上限 | 職員 40〜50 名程度 |
| 同時編集 | 後から保存した内容が残ります（**同じ部署を同時に編集しないでください**） |

---

## 合言葉の取り扱い

- 部署内でのみ共有し、外部には伝えない
- 職員の入れ替わりがあったら `resetPasscodes()` で作り直す
- 年度替わりに一斉更新する

**合言葉は「その部署の人である」ことしか確認できません。** 同じ部署の同僚であれば、他人の勤務を書き換えられます。
勤怠の正式な記録はハーモス勤怠を正とし、このツールは予定の作成と検証に使う、という位置づけにしてください。

## 困ったとき

| 症状 | 対処 |
|---|---|
| Googleのログイン画面が出る | デプロイのアクセス範囲を「全員」に。URL が `/dev` でないか確認 |
| 合言葉が違うと出る | 合言葉シートの値を確認。前後の空白に注意 |
| ログインできない（ロック中） | 10分待つ |
| 権限が「職員」のまま | 設定シートの管理者メールを確認 |
| 保存できない | 同時保存が集中している可能性。少し待って再編集 |
| 画面が古い | デプロイ時に「新バージョン」を選んだか確認 |
| setup が実行できない | コード.gs を選択しているか、保存済みかを確認 |

---

## バックアップ

`_data` シートが保存の本体です。月に一度、**ファイル → コピーを作成** でバックアップを取ってください。

確定した勤務表は、ツールの「印刷」から PDF で保存してください。出勤簿は法定の保存対象です。
